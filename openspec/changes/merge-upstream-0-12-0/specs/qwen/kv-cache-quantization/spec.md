# Spec Delta

## MODIFIED Requirements

### Requirement: キャッシュ機構との状態契約

システムは、RAM プレフィックスキャッシュ、実行中プレフィックスの共有、学習した境界と分岐点、安定チェックポイント、チェックポイントの選択と退避、有界の転送、クラッシュ耐性のあるディスク publication と起動時 index、ディスク staging、およびこれらを提供するキャッシュアダプタ層の各キャッシュ機構の下でも、KVarN の状態契約を満たさなければならない。(SHALL) これらの機構が保持・再利用するセッション状態の互換同一性キーは、KV 形式（プリセットとテール長）、state abi、チェックポイント境界の版（`checkpoint_frontier`）をすべて含まなければならない。(SHALL) 機構が KVarN の状態を保持・再利用する場合、その機構が用いる互換同一性も同じ項目を含まなければならない。(SHALL) KV 形式の異なる状態（FP16 と KVarN、プリセット間、テール長間）を、どの機構を通しても相互に再利用してはならない。(SHALL) これらの機構による再利用または復元の後に greedy（temperature 0）で生成したトークン列は、キャッシュを使わない同一条件の実行のトークン列と一致しなければならない。(SHALL) 同一性キーが一致しないスナップショットとディスクキャッシュは、再利用せず再計算しなければならない。(SHALL) ペイロード・量子化演算・読み出し経路を変更しない取り込みでは、互換同一性キーを変更してはならず、変更前に作成したディスクキャッシュを再利用できなければならない。(SHALL)

#### Scenario: RAM キャッシュ経由の再利用でトークン列が一致する
- **WHEN** `--kv-cache kvarn-k6v5 --kv-cache-tail 2048` で、同じシステムプロンプトを共有する新しい会話を順に 3 つ以上実行し、3 つ目以降が共有プレフィックス全体を RAM キャッシュから復元する
- **THEN** 各応答の greedy トークン列は、キャッシュを使わない同一条件の実行と一致し、起動ログの KV 形式は `kvarn-k6v5` のままである

#### Scenario: 実行中プレフィックスの共有でトークン列が一致する
- **WHEN** `kvarn-k6v5` テール長 2048 で、同じプロンプトの要求と、同じシステムプロンプトを持つ別々の要求をそれぞれ 2 つ以上同時に送り、後続の要求が先行要求の実行中プレフィックスを共有する
- **THEN** 各応答の greedy トークン列は、キャッシュを使わない同一条件の実行と一致する

#### Scenario: KV 形式が異なるキャッシュを再利用しない
- **WHEN** `kvarn-k6v5` テール長 2048 で作成した状態を、`--kv-cache` 未指定（`fp16`）、`--kv-cache kvarn-k4v4 --kv-cache-tail 512`、`--kv-cache kvarn-k6v5`（テール長未指定）のいずれかの条件で読み込もうとする
- **THEN** いずれの条件でも状態は再利用されず、生成されたトークン列はその条件のコールド実行と一致する

#### Scenario: 同一性キーの項目が異なるビルドのキャッシュは再利用されない
- **WHEN** 同一性キーの項目が異なるビルド（`checkpoint_frontier` を含まないビルドなど）で作成した FP16 と `kvarn-k6v5` テール長 2048 の `.kvc` ディスクキャッシュを、同じ KV 形式を指定して読み込む
- **THEN** 鍵の不一致によりディスクキャッシュから再利用されず、要求は再計算で完了し、greedy トークン列は同一条件のコールド実行と一致する

#### Scenario: 履歴の編集をまたいでも一致する
- **WHEN** `kvarn-k6v5` テール長 2048 で会話を進め、直近のメッセージの編集、または以前のユーザーメッセージの編集と以降のターンの削除（学習した境界の更新）を行った後に要求を評価する
- **THEN** 応答の greedy トークン列は、キャッシュを使わない同一条件の実行と一致する

#### Scenario: 分岐点の学習をまたいでも一致する
- **WHEN** `kvarn-k6v5` テール長 2048 で、復元先から分岐するプロンプトを新しい会話として実行し、その分岐点が学習された後に元の会話と新しい会話の両方を続ける
- **THEN** 各応答の greedy トークン列は、キャッシュを使わない同一条件の実行と一致する

#### Scenario: ディスク staging と再起動を経由した復元で一致する
- **WHEN** `kvarn-k4v4` テール長 512 で、ディスク staging の容量を 1 GiB に制限して成長する会話のチェックポイントをディスクへ書き出し、ディスクキャッシュからサーバを再起動した後に途中の分岐を復元する
- **THEN** 復元した分岐の応答の greedy トークン列は、キャッシュを使わない同一条件の実行と一致する

#### Scenario: 封印境界をまたぐ長い履歴で一致する
- **WHEN** `--context 32768` で 16K トークンを超える履歴を、`kvarn-k4v4` テール長 512 と `kvarn-k6v5` テール長 2048 のそれぞれでキャッシュから再開し、書き換えた応答から分岐する
- **THEN** 各応答の greedy トークン列は、キャッシュを使わない同一条件の実行と一致する

#### Scenario: 取り込みの前後で互換同一性キーが変わらない
- **WHEN** KVarN のペイロード・量子化演算・読み出し経路を変更しない upstream の取り込みの前に、`kvarn-k6v5` テール長 2048 と `--cache-disk` で `.kvc` ディスクキャッシュを作成し、取り込み後のビルドで同じディレクトリと同じ構成を指定して同じ要求を送る
- **THEN** 互換同一性キーの項目が変わらないためディスクキャッシュが再利用され、応答のプロンプト長と greedy トークン列は空のディレクトリでのコールド実行と一致する
