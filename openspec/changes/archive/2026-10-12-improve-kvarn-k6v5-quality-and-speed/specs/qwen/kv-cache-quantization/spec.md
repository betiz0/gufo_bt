# Spec Delta

## MODIFIED Requirements

### Requirement: 品質契約

システムは、KVarN 下でも品質を FP16 KV 経路の教師に対する一致トークン比較で評価できなければならない。(SHALL) 比較ではトークン化を 1 回だけ行い、同一の履歴を教師と候補に与え、各位置で全語彙の分布を比較する。評価は前置文脈 4K / 32K / 128K の直後 256 位置を対象とし、散文・コード・英語以外の言語を含み、平均 KL、中央値 KL、P99.9 KL、大逸脱率（KL が 1 nat を超える位置の割合）、top-1 一致率、教師トークン NLL の差を記録する。基準線 E_q8 / E_q4 は、同一の評価枠組み（ブロック 32、FP16 スケール、回転あり、sink あり）で計算し、テールを持たず、sink 以外の各行を書き込み直後に量子化する構成として、gpu-test ビルドだけで選択できる試験用の値（`--kv-cache baseline-q8` / `baseline-q4`）として提供し、release ビルドでは未知の値として拒否しなければならない。(SHALL) 基準線と `--kv-cache-tail` の併用は起動時エラーとしなければならない。(SHALL) 基準線の回転は正規化 Hadamard 行列（符号パターンなし）に固定し、KVarN の回転を変更しても追随させてはならない。(SHALL) 基準線は候補と同一の評価窓・同一の位置で測定し、p の基準点 M_E_q8 と分母 M_E_q4 − M_E_q8 には同じ窓の値を用いなければならない。(SHALL) 異なる評価窓で測った基準線を固定のものさしとして流用してはならない。(SHALL) 候補と基準線の比較は位置ごとに対応づけて行い、位置ごとの top-1 一致と argmax トークン ID を記録しなければならない。(SHALL) 各プリセットの適合テール長は、G0 でテール長 未指定・256・1024・2048 の 4 通りを評価して確定した値（品質優先 `kvarn-k6v5` は 2048、メモリ優先 `kvarn-k4v4` は 256）とし、変更 `improve-kvarn-k6v5-quality-and-speed` の最終判定（以下、本測定）では、両プリセットを適合テール長で再判定しなければならない。(SHALL) 本測定では適合テール長以外のテール長を再評価しない。合否は、判定指標 M（平均 KL、中央値 KL、大逸脱率、top-1 不一致率 = 1 − top-1 一致率）ごとに、各深度の評価窓の位置をプールして算出した値を用い、候補の「q8→q4 内分位置」 p(M) = (M_候補 − M_E_q8) / (M_E_q4 − M_E_q8) で判定しなければならない。(SHALL) p = 0 は E_q8 と同じ、p = 1 は E_q4 と同じ品質を意味する。品質優先プリセットは適合テール長で、全深度・全 4 指標で p ≤ 0.13 を満たさなければならない。(SHALL) p ≤ 0.10 は記録のみの努力目標とし、合否には用いない。(SHALL) メモリ優先プリセットは適合テール長で、全深度・全 4 指標で p ≤ 1 を満たさなければならない。(SHALL) M_E_q4 ≤ M_E_q8 となる深度・指標は p が定義できないため判定不能として報告し、その場合は未達とする。P99.9 KL と教師トークン NLL の差は記録するが、合否には用いない。教師の平均 NLL が 5 を超える評価窓は、事前登録した規則（design D14）により全候補と基準線から同じように除外し、除外した窓を成果物に列挙しなければならない。(SHALL) 本測定は、深度 4K・32K・128K のそれぞれで、D14 の除外後に 6 窓以上を対象としなければならない。(SHALL) 4K と 32K は G0 と異なる既存の評価窓（`t08-reduced`）の教師を再利用してよく、32K は除外後の窓数が 6 以上になるようにコーパスを追加する。128K は、改善策の確認に使う開発用の窓と、本測定の判定に使う判定用の窓を分け、判定用の窓には新しいシードのコーパスを用いなければならない。(SHALL) 判定用の窓では、本測定より前に教師と基準線以外を測定してはならない。(SHALL) 本測定では p の窓単位ブートストラップ 95% 区間を併記しなければならない。(SHALL) 許容位置 0.13 と努力目標 0.10 は本測定の前に固定し、結果を見て変更してはならない。(SHALL) いずれかの深度・指標で品質優先プリセットの p が 0.13 を超える場合は未達とし、bpv が増える改善の採用または許容位置の見直しは利用者の判断を仰がなければならない。(SHALL) `kvarn-k5v4` は同じ指標を記録するが、合否基準は課さない。テール長ごとの KL 指標・総量 bpv・セッションあたり KV 容量は、値を測った評価窓とともに `docs/models/qwen3.8-27b/README.md` に比較表として掲載しなければならない。(SHALL)

#### Scenario: 品質優先プリセットが q8_0 に近い位置にある
- **WHEN** 同一重み・同一ビルドで品質優先プリセットを適合テール長で E_q8・E_q4 と同じ評価枠組みで比較する
- **THEN** 4K と 32K では平均 KL・中央値 KL・大逸脱率・top-1 不一致率の p がすべて 0.13 以下であり、128K では p の値（平均 KL 0.161、大逸脱率 0.195、除外後 9 窓）が記録され、0.13 を満たさないため 128K の利用は未承認として文書に示される

#### Scenario: メモリ優先プリセットが q4_0 相当以上である
- **WHEN** 同一重み・同一ビルドで `kvarn-k4v4` を適合テール長で E_q8・E_q4 と同じ評価枠組みで比較する
- **THEN** 全深度で平均 KL・中央値 KL・大逸脱率・top-1 不一致率の p がすべて 1 以下である

#### Scenario: p が定義できない指標は判定不能になる
- **WHEN** ある深度・指標で E_q4 の値が E_q8 の値以下である
- **THEN** その指標は判定不能として報告され、その品質の合否は未達となる

#### Scenario: 基準線が候補と同じ窓で測られ、位置ごとに比較される
- **WHEN** gpu-test ビルドで基準線 E_q8 / E_q4 と候補を同一の評価窓・同一の位置で測定する
- **THEN** p の基準点と分母は同じ窓の値から計算され、位置ごとの top-1 一致と argmax トークン ID が記録され、異なる評価窓（G0 の窓など）で測った基準線は流用されない

#### Scenario: release ビルドは基準線の値を拒否する
- **WHEN** release ビルドの `gufo` を `--kv-cache baseline-q8` または `--kv-cache baseline-q4` を指定して起動する
- **THEN** 未知の値として非ゼロで終了し、基準線の書き込み経路は実行されない

#### Scenario: 基準線はテール長の指定を拒否する
- **WHEN** gpu-test ビルドで `--kv-cache baseline-q8 --kv-cache-tail 2048` を指定して起動する
- **THEN** 起動時エラーとなり、セッションは作成されない

#### Scenario: 努力目標が記録される
- **WHEN** 本測定で品質優先プリセットの p を評価する
- **THEN** p ≤ 0.10 は努力目標として記録され、合否の判定には用いられない

#### Scenario: 本測定が G0 と異なる評価窓で再判定される
- **WHEN** 本測定で品質基準を確認する
- **THEN** 深度 4K・32K・128K のそれぞれで G0 と異なる評価窓（4K・32K は `t08-reduced`、128K は新しいシードの判定用の窓。各深度で除外後 6 窓以上）に、品質優先 `kvarn-k6v5` テール長 2048 は許容位置 0.13、メモリ優先 `kvarn-k4v4` テール長 256 は許容位置 1 を適用し、p の窓単位ブートストラップ 95% 区間が併記され、深度 128K も G0 の判定の据え置きではなく本測定の結果で判定される。4K と 32K では 0.13 と 1 を適用し、128K では品質優先プリセットの 0.13 は未達（平均 KL 0.161・大逸脱率 0.195・9 窓）として記録され、メモリ優先プリセットは 1 を満たす

#### Scenario: 128K の判定用の窓が改善の確認に使われない
- **WHEN** 品質改善の効果を深度 128K で確かめる
- **THEN** 開発用の窓だけが使われ、判定用の窓の候補の測定は本測定の 1 回だけである

#### Scenario: テール長ごとの比較が掲載される
- **WHEN** 各プリセットをテール長 未指定・256・1024・2048 で評価した G0 の結果と、本測定の結果を掲載する
- **THEN** テール長ごとの KL 指標・総量 bpv・セッションあたり KV 容量が、値を測った評価窓とともに成果物に記録され、`docs/models/qwen3.8-27b/README.md` の比較表に掲載される

### Requirement: 性能契約

KVarN は KV メモリを減らすための機能であり、長文脈の生成速度とプロンプト処理速度が FP16 KV より下がることを受け入れる（design D19）。システムは、既存のベンチマーク手法（pp2048 / tg128、各点 1 回のウォームアップ済み測定、greedy。pp は各点 3 回の測定の中央値）で、同一の重み・プロンプト・キャッシュ履歴を使い、FP16 KV と交互に測定したとき、すべての KVarN プリセットについて、テール長未指定と L=2048 の両方で次を満たさなければならない。(SHALL) 測定に使う重みは Qwen3.8 27B の Q8_0 量子化 GGUF とし、そのファイルの SHA-256 を成果物に記録しなければならない。(SHALL) 比の分母となる FP16 KV の値は同じ測定系列の中で測定しなければならず、別の系列の測定値を流用してはならない。(SHALL) 深度 0〜4K の AR の tg は FP16 比 0.95 倍以上、深度 0 の DFlash2 の tg は 0.95 倍以上である。深度 32K 以上の AR と DFlash2 の tg、および全深度の pp は、基準値からの退行で判定する。基準値は、その項目を最初に測る判定（AR の tg と pp は G1、DFlash2 の tg は G2）で記録した FP16 比とし、以後の判定では、同じ点の FP16 比が基準値の 0.97 倍以上でなければならない。(SHALL) G4 の T-09 では、主構成 `kvarn-k5v4` テール長 2048 の深度 0・4K・32K の AR の tg を同じ測定系列の FP16 KV と交互に測り直し、深度 0〜4K の下限と基準値の 0.97 倍以上を満たさなければならない。(SHALL) その他のプリセット・テール長・点の tg と pp は、G1 の再判定と G2 の再測定の値を記録として用い、出典の成果物を併記する（design D23）。主構成 `kvarn-k5v4` テール長 2048 では、C8 AR の合計スループットが FP16 比 0.95 倍以上であり、起動から HTTP 応答可能になるまでの時間の悪化が 5% 以下でなければならない。(SHALL) 主構成と品質優先プリセット `kvarn-k6v5` テール長 2048 では、封印ステップを含む生成で、KVarN のトークン間レイテンシの p99 / p50 が、同一負荷の FP16 KV の p99 / p50 の 1.05 倍以下でなければならない。(SHALL) プリセット・テール長・深度ごとの tg と pp の FP16 比は、`docs/models/qwen3.8-27b/README.md` と `docs/CLI.md` に掲載し、KVarN が長文脈で FP16 KV より遅くなることを明記しなければならない。(SHALL) 変更 `improve-kvarn-k6v5-quality-and-speed` では、読み出しの作り直しと品質改善を行うため、品質優先プリセット `kvarn-k6v5` テール長 2048 の深度 8K と 128K の AR の tg と pp の FP16 比を、同じ測定系列の FP16 KV と交互に測って記録する。目標値による合否は課さない。(SHALL) 同変更での読み出しまたは量子化の各変更は、同じ手法で測った深度 8K と 128K の tg と pp の FP16 比を、その変更を加える前の値の 0.97 倍以上に保たなければならず、下回った変更は採用しないか、原因を解消してから採用しなければならない。(SHALL) 読み出しまたは量子化の演算を変更したビルドに対する、上記の深度 0〜4K の下限、深度 32K 以上の tg と全深度 pp の基準値からの退行、p99 / p50、C8 AR の合計スループット、起動時間の判定は、同変更では行わず、変更後のビルドで同一手法により測り直して後続の変更で適用しなければならない。(SHALL) 同変更の測定値と、既存の判定を繰り延べたことを `docs/models/qwen3.8-27b/BENCHMARKS.md` と `README.md` に記録しなければならない。(SHALL)
深度 4K の DFlash2 の tg は、深度 0 の DFlash2 の下限の対象とも、深度 32K 以上の基準値からの退行の対象ともせず、記録のみとする（利用者の決定、2026-10-05、D24）。

#### Scenario: 浅い文脈の速度が保たれる
- **WHEN** 深度 0 と 4K で各 KVarN プリセットの AR の tg を、テール長未指定と 2048 のそれぞれで FP16 KV と交互に測定する
- **THEN** 各プリセットの tg は FP16 比 0.95 倍以上である

#### Scenario: 基準値が記録される
- **WHEN** G1 の判定で、Q8_0 の重みを用いて深度 32K 以上の AR の tg と全深度の pp を、同じ測定系列の FP16 KV と交互に測定する
- **THEN** プリセット・テール長・深度ごとの FP16 比が基準値として、モデルの SHA-256 とともに成果物と `BENCHMARKS.md` に記録される

#### Scenario: 長文脈の速度と pp が退行しない
- **WHEN** G2 の判定ですべてのプリセットとテール長の基準値の点を、G4 の判定で主構成 `kvarn-k5v4` テール長 2048 の深度 32K の AR の tg を、同じ方法で測定する
- **THEN** 各点の FP16 比は基準値の 0.97 倍以上である

#### Scenario: 速度の低下が文書化される
- **WHEN** `docs/models/qwen3.8-27b/README.md` と `docs/CLI.md` の KVarN の記載を読む
- **THEN** プリセット・テール長・深度ごとの tg と pp の FP16 比（変更 `improve-kvarn-k6v5-quality-and-speed` の深度 8K・128K の記録を含む）と、KVarN が KV メモリを減らすための機能で長文脈では FP16 KV より遅くなることが記載されている

#### Scenario: 封印ステップがレイテンシを突出させない
- **WHEN** 封印ステップを含む生成のトークン間レイテンシを、`kvarn-k5v4` テール長 2048 と `kvarn-k6v5` テール長 2048 のそれぞれで、同一負荷の FP16 KV と測定する
- **THEN** KVarN の p99 / p50 は FP16 KV の p99 / p50 の 1.05 倍以下である

#### Scenario: 主構成の並列スループットと起動時間が保たれる
- **WHEN** `kvarn-k5v4` テール長 2048 で C8 AR の合計スループット（利用者あたり文脈 4096）と、起動から HTTP 応答可能になるまでの時間を、FP16 KV と測定する
- **THEN** C8 AR の合計スループットは FP16 比 0.95 倍以上で、起動時間の悪化は 5% 以下である

#### Scenario: 深度 8K と 128K の速度が記録される
- **WHEN** `kvarn-k6v5` テール長 2048 の深度 8K と 128K で AR の tg と pp を、同じ測定系列の FP16 KV と交互に測定する
- **THEN** FP16 比がモデルの SHA-256 と測定条件とともに記録され、目標値による合否は課されない

#### Scenario: 変更が速度を落とさない
- **WHEN** 読み出しまたは量子化の変更の前後で、`kvarn-k6v5` テール長 2048 の深度 8K と 128K の tg と pp を同じ手法で測定する
- **THEN** 変更後の各 FP16 比は変更前の値の 0.97 倍以上であり、下回った変更は採用されない

#### Scenario: 既存の判定の繰り延べが記録される
- **WHEN** 変更 `improve-kvarn-k6v5-quality-and-speed` を完了する
- **THEN** 深度 0〜4K の AR の tg の下限、深度 32K 以上の tg と全深度の pp の基準値からの退行、p99 / p50、C8 AR の合計スループット、起動時間は同変更では判定されず、変更後のビルドでの再測定と後続の変更での適用が `BENCHMARKS.md` と `README.md` に記録されている

### Requirement: KVarN 量子化パイプライン

システムは、RoPE 適用後に Q・K・V へ head_dim 256 の、直交する固定の Hadamard 系の回転（正規化 Hadamard 行列と、それに固定の符号パターンを掛けたものを含む）を適用し、GGUF 重みは変更してはならない。(SHALL) 注意出力では、部分注意のマージを含めた全寄与の統合後、SiLU ゲート適用の前に逆回転をちょうど 1 回だけ適用しなければならない。(SHALL) 封印は、回転済み F16 のタイルを二軸分散正規化（反復回数は定数、初期値 16、縮約順序は固定）した後に非対称 RTN で量子化する順序で行わなければならない。(SHALL) 品質改善のための量子化演算の変更（例: 量子化雑音のバイアス補正、回転の変種、正規化の数値の変更）は、`性能契約` の速度の非劣化（深度 8K と 128K の FP16 比を変更前の 0.97 倍以上に保つこと）を満たすものに限らなければならない。(SHALL) 変更を加えた場合も、封印は決定的であり、チャンク境界・検証幅・セッション並行度に依存せずビット一致し、回転の直交性（H·Hᵀ = I）と注意スコアの不変性を宣言限界内で保たなければならない。(SHALL) 総量 bpv が増える変更（例: メタデータの数値型を FP32 にすること）は、`KV 容量見積と実効ビット数の報告` の上限を満たす場合でも、採用前に利用者の確認を得なければならない。(SHALL) ペイロードの配置、量子化演算、または読み出しの演算を変更した場合のスナップショット版と同一性キーは、`KVarN の形式・演算の変更と版の更新` に従わなければならない。(SHALL)

#### Scenario: 回転が注意スコアを変えない
- **WHEN** 同じ入力に回転あり経路と回転なし経路で FP32 の QK スコアを計算する
- **THEN** 両者の差は宣言限界内に収まり、回転行列は H·Hᵀ = I を宣言限界内で満たす

#### Scenario: 逆回転が 1 回だけ適用される
- **WHEN** split-K または部分注意のマージを含む decode 経路と、マージを含まない経路で同じ入力の注意出力を得る
- **THEN** 両者の出力は宣言限界内で一致する

#### Scenario: 分散正規化が決定的である
- **WHEN** 同一の 128 トークン × 256 チャネル入力に対して GPU で封印を 2 回実行する
- **THEN** 正規化スケールと量子化コードはビット一致する

#### Scenario: 改善を加えても封印の性質が保たれる
- **WHEN** 量子化演算の変更（回転の変種を含む）を加えたビルドで、チャンク境界を変えて同じタイルを封印する
- **THEN** 正規化スケールと量子化コードはビット一致し、回転行列は H·Hᵀ = I を宣言限界内で満たす

## ADDED Requirements

### Requirement: KVarN の形式・演算の変更と版の更新

システムは、KVarN のペイロードの配置または量子化演算（回転・正規化・RTN を含む）を変更した場合、KVarN コンパクトスナップショットの版と状態 ABI（`state_abi`）を上げなければならない。(SHALL) 読み出し経路（decode・検証行・prefill）の演算の順序または算術を変更した場合は、ペイロードと量子化演算が同じでも状態 ABI を上げなければならない。(SHALL) いずれの場合も、プレフィックス再利用とディスクキャッシュの同一性キーが変更前の状態と一致してはならず、変更前に作成した KVarN のスナップショットとディスクキャッシュを復元・再利用してはならない。(SHALL) ペイロードの配置、量子化演算、読み出し経路の演算のいずれも変更しない場合、KVarN の形式・版・同一性キーは変更前と同じでなければならない。(SHALL) FP16 のスナップショット・保持バイト列・同一性キーは、どの場合も変更前と同じでなければならない。(SHALL)

#### Scenario: 変更前の KVarN 状態が再利用されない
- **WHEN** ペイロードまたは量子化演算を変更したビルドで、変更前に作成した KVarN のスナップショットまたはディスクキャッシュを読み込もうとする
- **THEN** 版と同一性キーの不一致により再利用・復元されず、要求は再計算で完了し、greedy トークン列はキャッシュを使わない同一条件の実行と一致する

#### Scenario: 読み出しの演算だけを変えても旧キャッシュは再利用されない
- **WHEN** 読み出し経路の演算だけを変更したビルドで、変更前のビルドが作成した KVarN のディスクキャッシュを同じ KV 形式で読み込もうとする
- **THEN** 状態 ABI を含む同一性キーの不一致により再利用されず、要求は再計算で完了し、greedy トークン列はキャッシュを使わない同一条件の実行と一致する

#### Scenario: 新しい版で保存・復元がビット一致する
- **WHEN** 変更後の版で KVarN セッションを保存して復元し、同じ入力を続けて評価する
- **THEN** 全 logits は中断しなかった同一セッションの logits とビット一致する

#### Scenario: 変更しない場合は形式が変わらない
- **WHEN** ペイロードの配置、量子化演算、読み出し経路の演算のいずれも変更しないビルドで、KVarN と FP16 のスナップショットと同一性キーを確認する
- **THEN** 版・バイト列・同一性キーは変更前と同じである
