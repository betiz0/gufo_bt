# Proposal

## Why

KVarN は前回の変更（`2026-10-08-add-kvarn-kv-cache-quantization`）で実装済みだが利用開始は見送られ、既定は `fp16` のままである。品質優先プリセット `kvarn-k6v5` テール長 2048（総量 6.08 bpv、q8_0 の 8.5 bpv の 72%）は、4K / 32K の T-08（`t08-reduced` の窓）では基準線 E_q8 と区別できない水準（最悪 p = 0.087）にある。一方、128K は G0 の暫定値 p = 0.143 のまま再判定されておらず、必達と言える状態になっていない。

p の測り方にも問題がある。T-08 以後のアンカー方式は、基準線 E_q8 / E_q4 を G0 の窓で、Phase 0 の試験経路のビルドで測った値を固定のものさしにしており、候補と同じ窓での比較になっていない。また 2026-10-09 のマージ後の再測定（G0 の窓）では、`kvarn-k6v5` L2048 の平均 KL の p が 32K で 0.202（窓 2、区間広）、128K で 0.154 と記録された（利用者受理の未達）。この再測定では基準線の値は前後で完全に一致しており、変化したのは候補側だった。生の平均 KL は 32K で 0.070 から 0.132 に上がり、その多くは 1〜2 位置の大きな KL スパイク（一部は prefill 直後の位置）による。原因は確定していない（`archive/2026-10-09-merge-upstream-main/tasks.md` のタスク 5.4）。

また長文脈の読み出しは展開と softmax が律速で、AR tg の FP16 比は 32K で約 0.85、128K で約 0.63 と遅い。

本変更は、候補と同一の窓・位置で測った基準線に対して、128K を含む全深度で `kvarn-k6v5` L=2048 の品質を確定する（必達 p ≤ 0.13、努力目標 p ≤ 0.10 は記録のみ）。あわせてメモリ優先 `kvarn-k4v4` L=256 の p ≤ 1 を同じ窓で再確認する。速度は FP16 に近づけられる範囲で改善する。

## What Changes

- **基準線の復元（gpu-test 専用）**: `--kv-cache baseline-q8|baseline-q4` を gpu-test プリセットだけで有効なコンパイル定義の下で受理し、書き込み時に sink（0〜127）以外の各行へ「回転（H·x）→ ブロック 32 の q8_0 / q4_0 量子化（FP16 スケール）→ 逆量子化 → 逆回転（Hᵀ）」を適用して既存の FP16 平面へ格納する。回転は正規化 Hadamard 行列に固定し、KVarN 側の回転を変えても追随させない。読み出し経路は変更しない。`--kv-cache-tail` との併用は起動時エラーにする。release ビルドでは未知の値として拒否する。G0 の値との差は記録するだけで、合否の条件にしない。
- **品質ハーネスの拡張**: 位置ごとの top-1 一致と argmax ID を units に追加し、p は同一ラベル内の基準線から計算する（G0 窓の値を固定のものさしにする D-27 のアンカーをやめる）。窓単位ブートストラップ 95% 区間は既存のものを使う。
- **評価窓の拡張**: 4K / 32K は `t08-reduced` の教師を再利用し、32K はコーパス追加で D14 の除外後 6 窓以上にする。128K は開発用の窓（G0 のコーパス 0〜2、教師はキャッシュ済み）と判定用の窓（新しいシード、除外後 6 窓以上）に分け、判定用の窓では本測定まで教師と基準線以外を測らない。1 窓 ≈10 分のため、1 単位を 5 窓以内に分割する。
- **品質契約の改定**: `kvarn-k6v5` L=2048 の許容位置を全深度・全 4 指標で **p ≤ 0.13（必達）** とし、128K を判定用の窓で再判定する。**p ≤ 0.10 は記録のみの努力目標**とする。メモリ優先 `kvarn-k4v4` L=256 も同じ窓で p ≤ 1 を再確認する。適合テール長は G0 の 4 通りの評価で確定した値（2048 と 256）を据え置き、他のテール長は再評価しない。基準線 E_q8 / E_q4 と教師は 1 回だけ測り、最終判定では候補のみ測る。
- **速度スパイク（二段階の go/no-go）**: `tools/bench/build.sh` でタイル単位の読み出し試作（1 ワークグループが KV ヘッド × split を担当し GQA 6 ヘッドでタイル展開を共有、マジックナンバー法の f16 変換、レーンごとのキー担当または WMMA、タイル単位の最大値・exp・再スケール）を作る。一次判定は、同じ単体ベンチ内で試作の読み出し時間が現行カーネルの **0.5 倍以下**で、spill や占有率の崩れがないこと。二次判定は Phase 2 の最初のタスクで、試作を本番の起動経路に仮組みし、`gufo bench` の 128K の深度コスト（tg のトークン時間の深度 128K と深度 0 の差）が現行の 131.6 ms の **0.5 倍以下**であることを確認する。どちらかを満たさなければ速度の作業はそこで止め、`EXPERIMENTS.md` に不採用として記録する。
- **go の場合の読み出しの作り直し**: `kernels/kvarn_read.hip` の `KvarnWalkPartition` をタイル単位の共通ウォーカーに置き換え、AR decode・split-K・因果検証（`QwenKvarnCausalDecodeKernel`）が同じヘルパーを同じ順序で使う。検証カーネルのキー 1 個ごとの `__syncthreads`（`kCausalChunk = kKeyBlock = 1`）と要素ごとの `KvarnUnpackCode` をなくす。prefill（tile / WMMA / batched）の要素ごとの `KvarnStoredKElement` / `KvarnStoredVElement` をタイル単位のベクトル展開に置き換える。演算順序が変わるため、KVarN の greedy 出力は旧ビルドと一致しなくなりうる（FP16 の契約は不変）。作り直しの後、`kvarn_consistency.py` を `kvarn-k6v5` L2048 で縮小実行し（32K と 128K で、封印境界を検証窓に含む単位を数件）、DFlash2 と AR の一致を確かめる。
- **品質改善（速度を落とさないものに限る）**: オフラインの原因調査で改善策を順位付けする。対象は 128K の高 d 位置（仮説: H1 遠方 K ノイズの softmax 分母への積み上げ、H2 メタデータの FP16 精度、H3 V の誤差、H4 二軸正規化の数値）と、G0 の窓の 32K で prefill 直後に出ているスパイク位置（本番経路と Phase 0 の試験経路の差の切り分け）。改善策（例: タイルごとの雑音バイアス補正、固定の符号パターンを掛けた Hadamard 回転、正規化の数値の変更、見つかった不具合の修正）は、8K / 128K の FP16 比を変更前の 0.97 倍以上に保つものだけを採用する。回転の義務は「直交する固定の Hadamard 系の回転（符号の固定パターンを含む）」に一般化する。bpv が増える案（例: K のゼロ点を FP32 にする ≈ +0.06 bpv）は、spec の上限 6.4 bpv の範囲内でも採用前にユーザーに確認する。
- **ペイロード・演算と同一性**: ペイロードの配置または量子化演算を変更した場合は、KVarN スナップショットの版と `state_abi` を上げる。読み出し経路の演算だけを変更した場合も `state_abi` を上げる。どちらの場合も旧版の KVarN 状態・キャッシュを再利用しない。いずれも変更しなければ形式はそのまま（FP16 のスナップショットと同一性キーは常に不変）。
- **速度の記録（合否なし）と非劣化**: `g1.py run --depths 8192,131072 --configs k6v5-t2048` を FP16 KV と同一系列で測り、tg と pp の FP16 比を Phase 0 の基準点と並べて記録する。読み出しまたは量子化の各変更は、その変更前の 0.97 倍以上を保つ。既存の速度の下限（深度 0〜4K の AR tg ≥ 0.95 等）と D19 の退行規則は、本変更では判定に使わず、読み出し変更後の再測定と再適用は後続の変更で行う（利用者の決定、2026-10-09）。
- **文書**: `docs/models/qwen3.8-27b/{QUALITY,BENCHMARKS,EXPERIMENTS,README}.md` と `docs/CLI.md` を更新する。

## Capabilities

### New Capabilities

- なし

### Modified Capabilities

- `qwen/kv-cache-quantization`: 品質契約（gpu-test 専用の同一窓基準線への切り替え、基準線とテール長の併用の拒否と回転の固定、k6v5 L=2048 の p ≤ 0.13 と k4v4 L=256 の p ≤ 1 の再判定、適合テール長の据え置き、128K の開発用と判定用の窓の分離、p ≤ 0.10 の記録のみの努力目標、位置ごとの top-1 一致の記録）、性能契約（8K / 128K の記録、各変更の 0.97 倍の非劣化、既存の下限と退行規則の後続変更への繰り延べ）、KVarN 量子化パイプライン（回転の義務の一般化、品質改善の速度非劣化）を変更し、形式・演算の変更時のスナップショット版と同一性キーの規則（`KVarN の形式・演算の変更と版の更新`）を追加する。

## 結果と判断 (2026-10-12)

判定用の窓（10 窓、D14 の除外後 9 窓、候補の測定は 1 回だけ）での最終判定は、
品質優先 `kvarn-k6v5` テール長 2048 が 4K / 32K で p ≤ 0.13 を満たし（最悪
0.125、32K の大逸脱率、8 窓）、**128K では未達**（最悪 0.195（大逸脱率）、平均
KL 0.161 [-0.002, 0.345]）だった。原因は本番 prefill 経路の F16 段階丸め
（task 4.2 の判定）で、章 6 の一次判定は no-go、章 7 の改善は採用しなかった
ため位置は変わっていない。メモリ優先 `kvarn-k4v4` テール長 256 は全深度で
p ≤ 1 を満たした。

利用者の判断（2026-10-12）により、**目標を改定して記録で終える**: 品質契約は
4K / 32K の 0.13 を必達、128K は測定値の記録とし、`kvarn-k6v5` テール長 2048
は 4K / 32K 用の構成として文書化する（128K の利用は未承認）。bpv を増やす
改善（k8 / q8_0 級）は採用しない。判定の全文と再現コマンドは
[docs/models/qwen3.8-27b/QUALITY.md](../../../../docs/models/qwen3.8-27b/QUALITY.md)
の最終判定節にある。

  - gpu-test 専用の基準線: `src/models/qwen/hip/kernels/{fused,prefill_rope}.hip`、`src/cli/kv_cache_options.hpp`、`src/models/qwen/hip/execution_policy.hpp`、`CMakeLists.txt`、`CMakePresets.json`、`tests/cli/kv_cache_test.py`。
  - 品質改善（回転の変種を採る場合を含む）: `src/models/qwen/hip/kernels/kvarn_device.hpp`、`kvarn_seal.hip`、`src/models/qwen/kvarn_reference.cpp` と CPU オラクルのテスト。
  - 版と同一性キー: `src/cli/serve/inference_backend.cpp`（`QwenStateAbiName`、永続 payload 版）、`src/models/qwen/hip/arena.cpp`（コンパクトスナップショットの版）。
  - ツール: `tests/models/qwen/hip/quality/kvarn_quality_eval.cpp`、`tools/qwen27b/kvarn_quality.py`、`tools/qwen27b/kvarn_read_compute_bench.hip`。`tools/qwen27b/kvarn_consistency.py` は既存のまま使う。
- 影響ドキュメント: `docs/models/qwen3.8-27b/{QUALITY,BENCHMARKS,EXPERIMENTS,README}.md`、`docs/CLI.md`。
- 影響なし: 既定 `fp16` の挙動・保持バイト列・同一性キー・スナップショット互換と、他モデル。プラットフォームは gfx1151 のみで、新しい依存は追加しない。
- 既知の非互換（BREAKING として扱わない）: 読み出しの作り直しまたは量子化の変更を行う場合、KVarN の greedy 出力は変更前のビルドと一致しなくなりうる（KVarN の出力のビルド間一致は既存の契約に含まれない）。また版と `state_abi` を上げるため、変更前の KVarN のスナップショットとディスクキャッシュは再利用されず再計算される。KVarN は既定ではなく利用開始前（既定は `fp16`）で、利用者から観測できる既定の挙動は変わらないため、これらは内部の非互換として扱い、BREAKING の表示とコミットの `!` は付けない。
