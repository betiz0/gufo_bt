# Spec Delta

## Purpose

Qwen3.8 27B のフル注意層 KV キャッシュを KVarN 方式で量子化して保持し、262,144 トークン文脈での KV メモリと読み出し帯域を削減しつつ、全注意経路・全セッション状態機能から透過的に読み出せるようにする。

## ADDED Requirements

### Requirement: 数値一致の定義

この仕様で「ビット一致」は出力バイト列の完全一致を意味し、「宣言限界内で一致」は、テストのソースに定数として宣言し、根拠とともに `docs/models/qwen3.8-27b/QUALITY.md` に記録した絶対誤差または相対誤差の上限以内に収まることを意味しなければならない。(SHALL) 宣言限界は、変更を通すために緩めてはならない。(SHALL)

#### Scenario: 宣言限界が記録されている
- **WHEN** 「宣言限界内で一致」を判定する各テストを確認する
- **THEN** テストのソースに上限値の定数があり、同じ値と根拠が `QUALITY.md` に記録されている

### Requirement: KV ストレージ形式の選択

システムは、フル注意層の KV キャッシュについて FP32・FP16 に加えて KVarN 系のストレージを選択でき、K と V のビット幅を独立に保持しなければならない。(SHALL) KVarN 系ストレージはメモリ優先プリセット `kvarn-k4v4`、中間プリセット `kvarn-k5v4`、および品質優先プリセット `kvarn-k6v5`（K 6 bit・V 5 bit）を提供しなければならない。(SHALL) 品質優先プリセットのビット幅は G0 の品質ゲート結果で `kvarn-k6v5` に確定し、その適合テール長は 2048 とする。既存の FP32・FP16 ストレージの挙動と保持バイト列は変更してはならない。(SHALL)

#### Scenario: 既定の FP16 で既存バイト列が保たれる
- **WHEN** KV 形式を指定せずに実行し、FP16 ストレージでセッションを進める
- **THEN** KV 領域のレイアウトと内容は変更前の FP16 経路とビット一致し、変更前に保存したスナップショットをそのまま読み込める

#### Scenario: プリセットごとに K/V ビット幅が独立に反映される
- **WHEN** `kvarn-k4v4` と `kvarn-k5v4` をそれぞれ選択して同一文脈長で実行する
- **THEN** K のタイルはそれぞれ 4 bit と 5 bit、V のタイルはどちらも 4 bit で格納され、実効 bpv の報告値は `kvarn-k5v4` の方が大きい

### Requirement: KV の 3 領域構成

システムは、KV キャッシュを sink・本体・テールの 3 領域で構成しなければならない。(SHALL) sink は絶対位置 0〜127 のトークンを F16 で保持する。本体は KV ヘッドごとの 128 トークン × 256 チャネルの封印済みタイルで構成し、タイル t は絶対位置 128+128t から 128+128t+127 を担当する。タイルには量子化コード、K 用のチャネル単位スケール・ゼロ点または V 用のトークン × グループ単位スケール・ゼロ点、およびチャネル正規化スケールとトークン正規化スケールを格納する。テールは未封印の行と、巻き戻しや検証のためにまだ F16 で必要な行を F16 で保持する。テール長 L は、`--kv-cache-tail` が指定されない場合はテールトークンを追加しない最小値 W とし、指定された場合はその値（256 以上 2048 以下の整数）としなければならない。(SHALL) L が W の場合も、128 行が揃っていないタイルの行と、位置で決まるビューがまだ F16 で読む行は F16 で保持する。 スケール類の数値型は FP16 または BF16 でなければならず、FP16 を基本とし、フェーズ 0 でダイナミックレンジ不足が観測された場合にのみ BF16 へ変更する。(SHALL) 領域はセッションごとに `max_context` 分を事前確保しなければならない。(SHALL)

#### Scenario: 文脈長が領域境界をまたぐ
- **WHEN** テール長 L が W（`--kv-cache-tail` 未指定）、256、2048 の各場合に、文脈長 127、128、129、128+L+127、128+L+128、128+L+129、256+L+127、256+L+128、256+L+129 トークンで decode を実行する
- **THEN** 各トークンの寄与が sink・本体・テールのいずれか 1 領域からちょうど 1 回読み出され、注意出力は FP64 参照と宣言限界内で一致する

#### Scenario: 最初の封印
- **WHEN** テール長 L が W と 2048 の各場合に、文脈長が 128+L+128 から 128+L+129 へ進む
- **THEN** タイル 0 が封印済みになり、位置 128+L+128 のクエリはタイル 0 を量子化値で読む

### Requirement: 位置で決まるビュー

システムは、クエリ位置 q が注意でタイル t を読むとき、タイル t の最終位置 e_t が q − L − 1 以下であれば量子化値で、それ以外であれば F16 値で読まなければならない。(SHALL) この規則は AR decode、投機検証の各行、prefill の各行、巻き戻し後の再計算で同一でなければならない。(SHALL) したがって最初の封印以後、クエリ q から見たテールの行数は L+1 以上 L+128 以下となる。システムは、ある位置のクエリがタイルを F16 で読む可能性が残っている間、そのタイルの F16 行を保持しなければならない。(SHALL) テールの容量は L+128+W 行以上でなければならず、W は最大検証行数と最大巻き戻しトークン数の大きい方である。(SHALL) L ≥ W は、指定可能な下限 256 が W 以上であることを静的に検査して保証し、指定された L の範囲とテールの容量はポリシー構築時に検査しなければならない。(SHALL)

#### Scenario: 検証行と AR が同じビューを使う
- **WHEN** 検証窓の途中に位置 e_t + L + 1 を含むドラフト幅 2〜8 の投機検証を行う
- **THEN** 窓内の各行は同じ位置の AR decode と同じ領域からタイル t を読み、各行の logits は AR decode の logits とビット一致する

#### Scenario: 検証行の書き込みが未封印行を上書きしない
- **WHEN** クエリから見たテールが L+128 行のときに、最大幅の検証行を書き込む
- **THEN** F16 で必要な既存行は上書きされず、検証行の注意出力は FP64 参照と宣言限界内で一致する

### Requirement: KVarN 量子化パイプライン

システムは、RoPE 適用後に Q・K・V へ head_dim 256 の正規化 Hadamard 回転を適用し、GGUF 重みは変更してはならない。(SHALL) 注意出力では、部分注意のマージを含めた全寄与の統合後、SiLU ゲート適用の前に逆回転をちょうど 1 回だけ適用しなければならない。(SHALL) 封印は、回転済み F16 のタイルを二軸分散正規化（反復回数は定数、初期値 16、縮約順序は固定）した後に非対称 RTN で量子化する順序で行わなければならない。(SHALL)

#### Scenario: 回転が注意スコアを変えない
- **WHEN** 同じ入力に回転あり経路と回転なし経路で FP32 の QK スコアを計算する
- **THEN** 両者の差は宣言限界内に収まり、回転行列は H·Hᵀ = I を宣言限界内で満たす

#### Scenario: 逆回転が 1 回だけ適用される
- **WHEN** split-K または部分注意のマージを含む decode 経路と、マージを含まない経路で同じ入力の注意出力を得る
- **THEN** 両者の出力は宣言限界内で一致する

#### Scenario: 分散正規化が決定的である
- **WHEN** 同一の 128 トークン × 256 チャネル入力に対して GPU で封印を 2 回実行する
- **THEN** 正規化スケールと量子化コードはビット一致する

### Requirement: 封印の入力契約

封印の対象は受理確定（commit）済みのトークンに限らなければならない。(SHALL) 投機検証で棄却されうる行は封印に含めてはならない。(SHALL) 封印結果は、そのタイルの 128 トークンの KV 値だけの関数でなければならない。(SHALL) 同じ KV 値に対しては、prefill のチャンク境界、検証幅、セッション並行度、封印のタイミングが異なっても、封印済みタイルのバイト列はビット一致しなければならない。(SHALL) HIP グラフ捕捉経路で封印の要否を判定するために、ホスト同期を追加してはならない。(SHALL) 定数チャネル（分散 0）には ε 下限を、極端な外れ値には定義済みのクランプを適用しなければならない。(SHALL) 非有限値を検出した場合は、ホスト同期を追加せずに既存の同期点で検出し、そのリクエストをエラーとして終了させ、そのセッションの状態を破棄して再利用・スナップショット化してはならない。(SHALL)

#### Scenario: 投機で棄却された行が封印に混入しない
- **WHEN** ドラフト幅 2〜8 と不揃いなコホートで、棄却を含む投機検証を行う
- **THEN** 封印済みタイルは棄却行を含まず、greedy 出力は自己回帰生成と一致する

#### Scenario: チャンク境界が違っても封印結果が一致する
- **WHEN** 同じ 256 行以上の KV 行を、一括 prefill 経路の書き込みと逐次 decode 経路の書き込みの 2 通りで処理する
- **THEN** 封印済みタイルのバイト列は両者でビット一致する

#### Scenario: スケール計算の異常値が定義どおり処理される
- **WHEN** 定数チャネル（分散 0）または極端な外れ値を含むタイルを封印する
- **THEN** ε 下限とクランプが適用され、正規化スケールと量子化コードはすべて有限値になる

#### Scenario: 非有限値でリクエストが失敗する
- **WHEN** 非有限値を含むタイルが封印される
- **THEN** そのリクエストはエラーで終了し、そのセッションは再利用もスナップショット化もされず、他のセッションの出力は影響を受けない

### Requirement: 3 領域を統合した注意読み出し

システムは、decode（スカラー / split-K / グラフ版）、検証行の因果 decode、prefill（tile / WMMA / batched）の読み出し経路で、sink・本体・テールを単一のオンライン softmax に統合しなければならない。(SHALL) decode と検証の経路では、逆量子化したテンソルをグローバルメモリに実体化してはならない。(SHALL) prefill の WMMA 経路では既存の有界な一時 FP16 ワークスペースへの逆量子化を許容するが、永続 KV 領域へ書き戻してはならない。(SHALL) テスト・ベンチ専用の GEMM 経路は KVarN をサポートせず、KVarN 選択時に呼び出された場合は明示的なエラーとしなければならない。(SHALL) KVarN が対応しない形状（Qwen3.8 27B のフル注意層以外の head 数・head_dim）で KVarN が選択された場合は起動時に明示的なエラーとし、FP16 への暗黙のフォールバックをしてはならない。(SHALL)

#### Scenario: decode が 3 領域を 1 回の softmax で統合する
- **WHEN** sink・封印済みタイル・テールがすべて非空の文脈で decode する
- **THEN** 出力は 3 領域すべてを含む FP64 参照と宣言限界内で一致する

#### Scenario: prefill 経路の出力が一致する
- **WHEN** 同じ入力を tile・WMMA・batched の各 prefill 経路で処理する
- **THEN** 各経路の出力は FP64 参照と宣言限界内で一致し、永続 KV 領域には逆量子化値が書き戻されない

#### Scenario: GEMM 経路は KVarN で拒否される
- **WHEN** KVarN ストレージを選択した状態で GEMM 注意経路を呼び出す
- **THEN** 明示的なエラーとなり、FP16 または FP32 の経路へ黙って切り替わらない

#### Scenario: 非対応の形状は暗黙にフォールバックしない
- **WHEN** KVarN が対応しない形状のモデル設定で KVarN を選択して起動する
- **THEN** 起動時にエラーとなり、FP16 経路へ黙って切り替わらない

### Requirement: セッション状態の整合

システムは、rollback とキャンセルをテール内の行を切り詰めるだけで完結させ、封印済みタイルを変更してはならない。(SHALL) rollback またはキャンセルの後に再計算されるクエリは、位置で決まるビューにより、中断しなかった同一セッションと同じ領域から読まなければならない。(SHALL) 継続とフォークはセッション間の独立性を保たなければならない。(SHALL) KVarN のコンパクトスナップショットは新しい版を用い、KVarN 種別、K/V ビット幅、テール長、sink・本体・テールの行数、スケール数値型を記録しなければならない。(SHALL) FP16 のスナップショットは変更前と同じ版とバイト列で書き出し、既存版（v1/v2）の読み込み互換を維持しなければならない。(SHALL) KVarN のプレフィックス再利用とディスクキャッシュの同一性キーには KV 形式（プリセットとテール長）を含め、プリセットまたはテール長の異なる状態を再利用してはならない。(SHALL) FP16 の同一性キーは変更前とバイト一致しなければならない。(SHALL) 復元後の全 logits は、中断しなかった同一セッションの logits とビット一致しなければならない。(SHALL) KVarN のスナップショットのバイト数は、タイル数・sink 行数・テール行数から design で定義したサイズ式で計算した値と一致しなければならない。(SHALL) 画像トークンと M-RoPE 位置を含む文脈にも同じ封印規則とビュー規則を適用しなければならない。(SHALL)

#### Scenario: キャンセルが封印をまたいでも一致する
- **WHEN** 検証窓内に位置 e_t + L + 1 を含む投機検証の直後にキャンセルし、スナップショットを保存・復元して生成を続ける
- **THEN** 封印済みタイルは変化せず、復元後の全 logits は中断しなかった同一セッションの logits とビット一致する

#### Scenario: スナップショットの保存・復元で logits が一致する
- **WHEN** KVarN セッションを保存して復元し、同じ入力を続けて評価する
- **THEN** 全 logits が中断しなかった同一セッションの logits とビット一致し、旧版スナップショットは読み込め、破損データと、KV 形式またはテール長の異なるキャッシュは拒否される

#### Scenario: FP16 の既存ディスクキャッシュが再利用される
- **WHEN** 変更前のビルドで作成した FP16 の `.kvc` を、変更後のビルドで `--kv-cache` なしで読み込む
- **THEN** 同一性キーが一致して再利用される

#### Scenario: 継続フォークが独立する
- **WHEN** 32K トークンの文脈から 2 つのブランチへ継続フォークする
- **THEN** 各ブランチの封印済みタイルとテールは他方の更新の影響を受けない

#### Scenario: 画像を含む文脈で封印が働く
- **WHEN** 画像トークンを含み M-RoPE 位置を使う文脈で、封印境界をまたいで生成する
- **THEN** 封印とビューは絶対位置の規則どおりに適用され、スナップショット復元後の logits はビット一致する

### Requirement: KV 容量見積と実効ビット数の報告

システムは、メモリ見積とセッション容量計算に KVarN のサイズ式を用い、テール長と実効 bpv（本体のみ、および総量）を起動ログと `gufo bench` の出力に報告しなければならない。(SHALL) テール長の全範囲（未指定および 256〜2048）で、メモリ優先プリセットは本体 4.5 bpv 以下、262,144 トークン容量時の総量 4.6 bpv 以下でなければならない。(SHALL) 品質優先プリセットはテール長の全範囲で総量 6.4 bpv 以下（q8_0 の 8.5 bpv の 75% 以下）でなければならない。(SHALL) bpv はスケール・ゼロ点・正規化スケール・sink・テールを含めて数え、テールトークンの追加分はテール行として総量 bpv とセッションあたり KV 容量に含める。封印用の一時領域は既存スクラッチ内に収め、収まらない場合はセッションあたりの固定上限を見積に含めなければならない。(SHALL) HIP のピーク割当をベンチマーク文書のメモリ表の形式で報告しなければならない。(SHALL)

#### Scenario: 見積がセッション数と文脈長を反映する
- **WHEN** `--sessions` と `--context` を指定して KVarN 形式の見積を取得する
- **THEN** 報告される KV 容量は選択したプリセットのサイズ式と一致し、FP16 指定時より小さく、実確保量と一致する

#### Scenario: 報告された bpv が受入基準を満たす
- **WHEN** `kvarn-k4v4` を `--kv-cache-tail` 未指定と `--kv-cache-tail 2048` でそれぞれ選択して起動ログと `gufo bench` の出力を読む
- **THEN** どちらもテール長が報告され、本体 bpv は 4.5 以下、262,144 トークン容量時の総量 bpv は 4.6 以下として報告される

### Requirement: 品質契約

システムは、KVarN 下でも品質を FP16 KV 経路の教師に対する一致トークン比較で評価できなければならない。(SHALL) 比較ではトークン化を 1 回だけ行い、同一の履歴を教師と候補に与え、各位置で全語彙の分布を比較する。評価は前置文脈 4K / 32K / 128K の直後 256 位置を対象とし、散文・コード・英語以外の言語を含み、平均 KL、中央値 KL、P99.9 KL、大逸脱率（KL が 1 nat を超える位置の割合）、top-1 一致率、教師トークン NLL の差を記録する。基準線 E_q8 / E_q4 は同一の評価枠組み（ブロック 32、FP16 スケール、回転あり、sink あり）で計算し、テールを持たず、sink 以外の各行を書き込み直後に量子化しなければならない。(SHALL) KVarN の各プリセットはテール長 未指定・256・1024・2048 の 4 通りで評価し、基準を全深度で満たす最小のテール長をそのプリセットの適合テール長として確定しなければならない。(SHALL) 合否は、判定指標 M（平均 KL、中央値 KL、大逸脱率、top-1 不一致率 = 1 − top-1 一致率）ごとに、各深度で 3 コーパスにプールした位置から算出した値を用い、候補の「q8→q4 内分位置」 p(M) = (M_候補 − M_E_q8) / (M_E_q4 − M_E_q8) で判定しなければならない。(SHALL) p = 0 は E_q8 と同じ、p = 1 は E_q4 と同じ品質を意味する。品質優先プリセットは適合テール長で、全深度・全 4 指標で p ≤ 0.15 を満たさなければならない。(SHALL) メモリ優先プリセットは適合テール長で、全深度・全 4 指標で p ≤ 1 を満たさなければならない。(SHALL) M_E_q4 ≤ M_E_q8 となる深度・指標は p が定義できないため判定不能として報告し、その場合は G0 を未達とする。P99.9 KL と教師トークン NLL の差は記録するが、合否には用いない。教師の平均 NLL が 5 を超える評価窓は、事前登録した規則（design D14）により全候補と基準線から同じように除外し、除外した窓を成果物に列挙しなければならない。(SHALL) この基準は G0 の測定結果を見た後に定めたもの（design D17）であるため、フェーズ 4 の本測定は G0 で使っていない評価窓（別シードで文書順を変えた新規コーパス、各深度 6 窓以上）に同じ基準と同じ許容位置 0.15 を適用して再判定し、結果に合わせて許容位置を変更してはならない。(SHALL) 本測定では p の窓単位ブートストラップ 95% 区間を併記しなければならない。(SHALL) いずれのテール長でも基準を満たさないプリセットがあれば、G0 は未達とする。両プリセットの基準はフェーズ 0 の G0 で合否を判定し、フェーズ 4 の本測定で再確認しなければならない。(SHALL) `kvarn-k5v4` は同じ指標を記録するが、合否基準は課さない。テール長ごとの KL 指標・総量 bpv・セッションあたり KV 容量は、`docs/models/qwen3.8-27b/README.md` に比較表として掲載しなければならない。(SHALL)

#### Scenario: 品質優先プリセットが q8_0 に近い位置にある
- **WHEN** 同一重み・同一ビルドで品質優先プリセットを適合テール長で E_q8・E_q4 と同じ評価枠組みで比較する
- **THEN** 全深度で平均 KL・中央値 KL・大逸脱率・top-1 不一致率の p がすべて 0.15 以下である

#### Scenario: メモリ優先プリセットが q4_0 相当以上である
- **WHEN** 同一重み・同一ビルドで `kvarn-k4v4` を適合テール長で E_q8・E_q4 と同じ評価枠組みで比較する
- **THEN** 全深度で平均 KL・中央値 KL・大逸脱率・top-1 不一致率の p がすべて 1 以下である

#### Scenario: p が定義できない指標は判定不能になる
- **WHEN** ある深度・指標で E_q4 の値が E_q8 の値以下である
- **THEN** その指標は判定不能として報告され、G0 は未達になる

#### Scenario: 本測定が G0 と異なる評価窓で再判定される
- **WHEN** フェーズ 4 の本測定で品質基準を再確認する
- **THEN** G0 で使っていない評価窓（各深度 6 窓以上）に許容位置 0.15 のまま適用され、p の窓単位ブートストラップ 95% 区間が併記される

#### Scenario: テール長ごとの比較が掲載される
- **WHEN** 各プリセットをテール長 未指定・256・1024・2048 で評価する
- **THEN** テール長ごとの KL 指標・総量 bpv・セッションあたり KV 容量が成果物に記録され、`docs/models/qwen3.8-27b/README.md` の比較表に掲載される

### Requirement: 品質ゲート

システムは、KVarN 下で非有限の logits を 1 件も出力してはならない。(SHALL) DFlash2 の greedy 出力は、深度 0〜128K で AR と一致しなければならない。(SHALL) 自己回帰の誤差累積を、数学推論とコードを含む固定の問題セットで FP16 KV と比較して評価しなければならない。(SHALL) 品質優先プリセットでは、適合テール長で、正答率の差（KVarN − FP16）のブートストラップ 95% 区間が 0 を含み、かつその下限が −δ を上回り、かつ試行数が N 以上でなければならない。(SHALL) 品質優先プリセットは、適合テール長で、前置文脈 32K と 128K の位置に置いた事実を直近の文脈に手掛かりがない状態で参照させる固定の長距離参照タスクでも、FP16 KV に対する正答率の差のブートストラップ 95% 区間の下限が −δ_ret を上回り、かつ試行数が N_ret 以上でなければならない。(SHALL) 非劣性マージンは δ = 0.03（デコード型）と δ_ret = 0.05（長距離参照型）、最小試行数は N = 200 と N_ret = 128 とする。問題セットは、デコード型が数学推論 100 問とコード 100 問、長距離参照型が 32K と 128K に事実を置く 128 問とし、固定した問題ファイルとその SHA-256 を成果物に記録する（いずれも G0 で確定）。評価成果物としてモデルと教師のハッシュ、プロンプトとトークン列のハッシュ、設定、スキーマ版を記録し、大容量の logits は Git の外に置かなければならない。(SHALL)

#### Scenario: 非有限 logits が発生しない
- **WHEN** 品質評価の全深度・全テール長で KVarN セッションを実行する
- **THEN** 非有限の logits は 0 件である

#### Scenario: DFlash2 が AR と一致する
- **WHEN** KVarN 下で DFlash2 の検証付き生成を深度 0〜128K で実行する
- **THEN** greedy 出力は AR 生成と一致する

#### Scenario: デコード型評価が非劣性を満たす
- **WHEN** 適合テール長の品質優先プリセットと FP16 KV で固定の問題セットを N 回以上試行する
- **THEN** 正答率の差のブートストラップ 95% 区間は 0 を含み、下限は −δ を上回る

#### Scenario: 長距離参照タスクが非劣性を満たす
- **WHEN** 適合テール長の品質優先プリセットと FP16 KV で、32K と 128K に事実を置いた固定の長距離参照問題を N_ret 回以上試行する
- **THEN** 正答率の差のブートストラップ 95% 区間の下限は −δ_ret を上回る

### Requirement: 性能契約

システムは、既存のベンチマーク手法（pp2048 / tg128、各点 1 回のウォームアップ済み測定、greedy）で、同一の重み・プロンプト・キャッシュ履歴を使い、FP16 KV と交互に測定したとき、すべての KVarN プリセットについて、テール長未指定と L=2048 の両方で次の速度を満たさなければならない。(SHALL) 測定に使う重みは Qwen3.8 27B の Q8_0 量子化 GGUF とし、そのファイルの SHA-256 を成果物に記録しなければならない。(SHALL) 比の分母となる FP16 KV の値は同じ測定系列の中で測定しなければならず、別の系列の測定値を流用してはならない。(SHALL) AR の tg は深度 0〜4K で FP16 比 0.95 倍以上、深度 32K 以上で 1.00 倍以上である。pp は全深度で FP16 比 0.95 倍以上である。DFlash2 の tg は深度 0 で 0.95 倍以上、深度 32K 以上で 1.00 倍以上である。C8 AR の合計スループットは FP16 比 0.95 倍以上である。起動から HTTP 応答可能になるまでの時間の悪化は 5% 以下である。封印ステップを含む生成の p99 トークン間レイテンシは、同一負荷の FP16 KV に対して 5% 以下の増加である。加えて、メモリ優先プリセットの深度 128K の AR tg の FP16 比 R は、同じ測定から算出する理想利得 G* に対して R ≥ 1 + f·G*（f = 0.5）を満たさなければならない。(SHALL) G* は、FP16 KV の深度 d と深度 0 のトークンあたり時間 T_FP16(d)・T_FP16(0) と、1 トークンの生成で読む KV のバイト数 B_FP16(d)・B_KVarN(d)（design D5 のサイズ式による計算値）から、BW = B_FP16(d) / (T_FP16(d) − T_FP16(0))、G* = T_FP16(d) / (T_FP16(0) + B_KVarN(d) / BW) − 1 として算出しなければならない（design D18）。(SHALL) 品質優先プリセットだけが深度 32K 以上の AR tg で 1.00 倍に届かず、他の KVarN プリセットはその深度で届いている場合は、原因を調査しなければならない。(SHALL) design D18 の判定基準で主因が実行ハードウェア（Strix Halo、gfx1151）にあると判定されたときに限り、品質優先プリセットのその深度の基準を、測定値と原因分析の記録で代えることができる。

#### Scenario: 浅い文脈の速度が保たれる
- **WHEN** 深度 0 と 4K で各 KVarN プリセットの AR の tg を、テール長未指定と 2048 のそれぞれで FP16 KV と交互に測定する
- **THEN** 各プリセットの tg は FP16 比 0.95 倍以上である

#### Scenario: 長文脈で速度が向上する
- **WHEN** 深度 32K 以上で各 KVarN プリセットの AR の tg を、テール長未指定と 2048 のそれぞれで、同じ測定系列の FP16 KV と交互に測定する
- **THEN** 各プリセットの tg は FP16 比 1.00 倍以上であり、メモリ優先プリセットの 128K の比 R は R ≥ 1 + f·G* を満たす

#### Scenario: 理想利得が同じ測定から算出される
- **WHEN** Q8_0 の重みで深度 128K のメモリ優先プリセットを判定する
- **THEN** 成果物にモデルの SHA-256、T_FP16(0)、T_FP16(d)、B_FP16(d)、B_KVarN(d)、BW、G*、R、閾値 1 + f·G* が記録され、T_FP16 はその測定系列で測った値である

#### Scenario: 品質優先プリセットの未達がハードウェア起因と判定される
- **WHEN** 品質優先プリセットだけが深度 32K 以上の AR tg で 1.00 倍に届かない
- **THEN** design D18 の判定基準による原因分析が記録され、主因がハードウェアと判定された場合に限り、その深度の基準が測定値と原因分析の記録で代えられる

#### Scenario: 封印ステップがレイテンシを突出させない
- **WHEN** 封印ステップを含む生成のトークン間レイテンシを、同一負荷の FP16 KV と測定する
- **THEN** KVarN の p99 は FP16 KV の p99 に対して 5% 以下の増加である

### Requirement: 決定性

システムは、同じシードと同じ設定での再生を KVarN 下でも維持しなければならない。(SHALL)

#### Scenario: 同一シードで再生が一致する
- **WHEN** 同じシードと設定で、封印境界をまたぐ KVarN のサンプリング生成を 2 回実行する
- **THEN** 生成されたトークン列は一致する
