# Spec Delta

## MODIFIED Requirements

### Requirement: KV ストレージ形式の選択

システムは、フル注意層の KV キャッシュについて FP32・FP16 に加えて KVarN 系のストレージを選択でき、K と V のビット幅を独立に保持しなければならない。(SHALL) KVarN 系ストレージはメモリ優先プリセット `kvarn-k4v4`、中間プリセット `kvarn-k5v4`、および品質優先プリセット `kvarn-k6v5`（K 6 bit・V 5 bit）を提供しなければならない。(SHALL) 品質優先プリセットのビット幅は G0 の品質ゲート結果で `kvarn-k6v5` に確定し、その適合テール長は 2048 とする。既存の FP32・FP16 ストレージのレイアウト、書き込みの挙動、保持バイト列は変更してはならない。(SHALL) ただし、FP16 の decode と検証行の注意の算術を `qwen/decode-attention` に従って変更したビルドでは、その算術の違いで後続の層の KV の値が変わることを許容し、`セッション状態の整合` に従って FP16 の互換同一性を変えなければならない。(SHALL)

#### Scenario: 既定の FP16 で既存バイト列が保たれる
- **WHEN** KV 形式を指定せずに実行し、FP16 ストレージでセッションを進める
- **THEN** KV 領域のレイアウトは変更前の FP16 経路と同一であり、FP16 の decode と検証行の注意の算術が同じビルドどうしでは内容もビット一致し、変更前の版のスナップショットの形式を読み込める

#### Scenario: プリセットごとに K/V ビット幅が独立に反映される
- **WHEN** `kvarn-k4v4` と `kvarn-k5v4` をそれぞれ選択して同一文脈長で実行する
- **THEN** K のタイルはそれぞれ 4 bit と 5 bit、V のタイルはどちらも 4 bit で格納され、実効 bpv の報告値は `kvarn-k5v4` の方が大きい

### Requirement: セッション状態の整合

システムは、rollback とキャンセルをテール内の行を切り詰めるだけで完結させ、封印済みタイルを変更してはならない。(SHALL) rollback またはキャンセルの後に再計算されるクエリは、位置で決まるビューにより、中断しなかった同一セッションと同じ領域から読まなければならない。(SHALL) 継続とフォークはセッション間の独立性を保たなければならない。(SHALL) KVarN のコンパクトスナップショットは新しい版を用い、KVarN 種別、K/V ビット幅、テール長、sink・本体・テールの行数、スケール数値型を記録しなければならない。(SHALL) FP16 のスナップショットは同じコミットの upstream のビルドと同じ版と形式で書き出し、既存版（v1/v2）の読み込み互換を維持しなければならない。(SHALL) FP16 の decode と検証行の注意の算術が upstream と同じビルドでは、FP16 のスナップショットのバイト列も同じコミットの upstream のビルドと同じでなければならない。(SHALL) KVarN のプレフィックス再利用とディスクキャッシュの同一性キーには KV 形式（プリセットとテール長）を含め、プリセットまたはテール長の異なる状態を再利用してはならない。(SHALL) FP16 の decode と検証行の注意の算術が upstream と同じビルドでは、FP16 の同一性キーは、同じコミットの upstream のビルドが生成する同一性キーとバイト一致しなければならない。(SHALL) その算術を upstream から変えたビルドでは、FP16 の同一性キーは、同じコミットの upstream のビルドが生成する同一性キーに、その算術を表す項目を加えたものとバイト一致しなければならず、算術を変えるたびに項目の値を変えなければならない。(SHALL) この項目は FP32 と KVarN の同一性キーに加えてはならない。(SHALL) 復元後の全 logits は、中断しなかった同一セッションの logits とビット一致しなければならない。(SHALL) KVarN のスナップショットのバイト数は、タイル数・sink 行数・テール行数から design で定義したサイズ式で計算した値と一致しなければならない。(SHALL) 画像トークンと M-RoPE 位置を含む文脈にも同じ封印規則とビュー規則を適用しなければならない。(SHALL)

#### Scenario: キャンセルが封印をまたいでも一致する
- **WHEN** 検証窓内に位置 e_t + L + 1 を含む投機検証の直後にキャンセルし、スナップショットを保存・復元して生成を続ける
- **THEN** 封印済みタイルは変化せず、復元後の全 logits は中断しなかった同一セッションの logits とビット一致する

#### Scenario: スナップショットの保存・復元で logits が一致する
- **WHEN** KVarN セッションを保存して復元し、同じ入力を続けて評価する
- **THEN** 全 logits が中断しなかった同一セッションの logits とビット一致し、旧版スナップショットは読み込め、破損データと、KV 形式またはテール長の異なるキャッシュは拒否される

#### Scenario: FP16 の既存ディスクキャッシュが再利用される
- **WHEN** `--kv-cache` を指定せずに、FP16 の互換同一性キーとディスクキャッシュの再利用可能性を検証する
- **THEN** 同一性キーを生成する式と行の並びが、FP16 の decode と検証行の注意の算術を表す項目を除いて同じコミットの upstream のビルドと同一であることがコード上で確認され、既存の FP16 テストが退行なく通ることで、同一性キーが一致する `.kvc` ディスクキャッシュの再利用が担保される

#### Scenario: decode 注意の算術が異なる FP16 キャッシュは再利用されない
- **WHEN** FP16 の decode と検証行の注意の算術を変えたビルドで、変える前のビルドまたは同じコミットの upstream のビルドが作った FP16 の `.kvc` ディスクキャッシュを、同じディレクトリと同じ構成を指定して読み込む
- **THEN** 同一性キーの不一致により再利用されず、要求は再計算で完了し、greedy トークン列はキャッシュを使わない同一条件の実行と一致する

#### Scenario: FP16 の注意の変更で FP32 と KVarN の同一性キーが変わらない
- **WHEN** FP16 の decode と検証行の注意の算術だけを変えたビルドで、FP32 と KVarN の各プリセットの同一性キーを変える前のビルドと比べる
- **THEN** 同一性キーはバイト一致する

#### Scenario: 継続フォークが独立する
- **WHEN** 32K トークンの文脈から 2 つのブランチへ継続フォークする
- **THEN** 各ブランチの封印済みタイルとテールは他方の更新の影響を受けない

#### Scenario: 画像を含む文脈で封印が働く
- **WHEN** 画像トークンを含み M-RoPE 位置を使う文脈で、封印境界をまたいで生成する
- **THEN** 封印とビューは絶対位置の規則どおりに適用され、スナップショット復元後の logits はビット一致する

### Requirement: 性能契約

KVarN は KV メモリを減らすための機能であり、長文脈の生成速度とプロンプト処理速度が FP16 KV より下がることを受け入れる（design D19）。システムは、既存のベンチマーク手法（pp2048 / tg128、各点 1 回のウォームアップ済み測定、greedy。pp は各点 3 回の測定の中央値）で、同一の重み・プロンプト・キャッシュ履歴を使い、FP16 KV と交互に測定したとき、すべての KVarN プリセットについて、テール長未指定と L=2048 の両方で次を満たさなければならない。(SHALL) 測定に使う重みは Qwen3.8 27B の Q8_0 量子化 GGUF とし、そのファイルの SHA-256 を成果物に記録しなければならない。(SHALL) 比の分母となる FP16 KV の値は同じ測定系列の中で測定しなければならず、別の系列の測定値を流用してはならない。(SHALL) 深度 0〜4K の AR の tg は FP16 比 0.95 倍以上、深度 0 の DFlash2 の tg は 0.95 倍以上である。深度 32K 以上の AR と DFlash2 の tg、および全深度の pp は、基準値からの退行で判定する。基準値は、その項目を最初に測る判定（AR の tg と pp は G1、DFlash2 の tg は G2）で記録した FP16 比とし、以後の判定では、同じ点の FP16 比が基準値の 0.97 倍以上でなければならない。(SHALL) FP16 KV の decode または検証行の注意の演算を置き換えた場合は、置き換えたビルドで、KVarN の読み出しを変更する前に、すべてのプリセット・テール長について、深度 32K 以上の AR と DFlash2 の tg の基準値の各点の FP16 比を同じ手法で FP16 KV と交互に測り直し、その値を新しい基準値としなければならない。(SHALL) pp の基準値は、FP16 の prefill の注意を置き換えない限り変えてはならない。(SHALL) 測り直した基準値は、置き換え前の基準値と並べて、モデルの SHA-256 と測定条件とともに `docs/models/qwen3.8-27b/BENCHMARKS.md` に記録しなければならない。(SHALL) G4 の T-09 では、主構成 `kvarn-k5v4` テール長 2048 の深度 0・4K・32K の AR の tg を同じ測定系列の FP16 KV と交互に測り直し、深度 0〜4K の下限と基準値の 0.97 倍以上を満たさなければならない。(SHALL) その他のプリセット・テール長・点の tg と pp は、G1 の再判定と G2 の再測定の値を記録として用い、出典の成果物を併記する（design D23）。主構成 `kvarn-k5v4` テール長 2048 では、C8 AR の合計スループットが FP16 比 0.95 倍以上であり、起動から HTTP 応答可能になるまでの時間の悪化が 5% 以下でなければならない。(SHALL) 主構成と品質優先プリセット `kvarn-k6v5` テール長 2048 では、封印ステップを含む生成で、KVarN のトークン間レイテンシの p99 / p50 が、同一負荷の FP16 KV の p99 / p50 の 1.05 倍以下でなければならない。(SHALL) プリセット・テール長・深度ごとの tg と pp の FP16 比は、`docs/models/qwen3.8-27b/README.md` と `docs/CLI.md` に掲載し、KVarN が長文脈で FP16 KV より遅くなることを明記しなければならない。(SHALL) 変更 `improve-kvarn-k6v5-quality-and-speed` では、読み出しの作り直しと品質改善を行うため、品質優先プリセット `kvarn-k6v5` テール長 2048 の深度 8K と 128K の AR の tg と pp の FP16 比を、同じ測定系列の FP16 KV と交互に測って記録する。目標値による合否は課さない。(SHALL) 同変更での読み出しまたは量子化の各変更は、同じ手法で測った深度 8K と 128K の tg と pp の FP16 比を、その変更を加える前の値の 0.97 倍以上に保たなければならず、下回った変更は採用しないか、原因を解消してから採用しなければならない。(SHALL) 読み出しまたは量子化の演算を変更したビルドに対する、上記の深度 0〜4K の下限、深度 32K 以上の tg と全深度 pp の基準値からの退行、p99 / p50、C8 AR の合計スループット、起動時間の判定は、同変更では行わず、変更後のビルドで同一手法により測り直して後続の変更で適用しなければならない。(SHALL) 同変更の測定値と、既存の判定を繰り延べたことを `docs/models/qwen3.8-27b/BENCHMARKS.md` と `README.md` に記録しなければならない。(SHALL)
深度 4K の DFlash2 の tg は、深度 0 の DFlash2 の下限の対象とも、深度 32K 以上の基準値からの退行の対象ともせず、記録のみとする（利用者の決定、2026-10-05、D24）。

#### Scenario: 浅い文脈の速度が保たれる
- **WHEN** 深度 0 と 4K で各 KVarN プリセットの AR の tg を、テール長未指定と 2048 のそれぞれで FP16 KV と交互に測定する
- **THEN** 各プリセットの tg は FP16 比 0.95 倍以上である

#### Scenario: 基準値が記録される
- **WHEN** G1 の判定で、Q8_0 の重みを用いて深度 32K 以上の AR の tg と全深度の pp を、同じ測定系列の FP16 KV と交互に測定する
- **THEN** プリセット・テール長・深度ごとの FP16 比が基準値として、モデルの SHA-256 とともに成果物と `BENCHMARKS.md` に記録される

#### Scenario: 長文脈の速度と pp が退行しない
- **WHEN** G2 の判定ですべてのプリセットとテール長の基準値の点を、G4 の判定で主構成 `kvarn-k5v4` テール長 2048 の深度 32K の AR の tg を、同じ方法で測定する
- **THEN** 各点の FP16 比は基準値の 0.97 倍以上である

#### Scenario: 速度の低下が文書化される
- **WHEN** `docs/models/qwen3.8-27b/README.md` と `docs/CLI.md` の KVarN の記載を読む
- **THEN** プリセット・テール長・深度ごとの tg と pp の FP16 比（変更 `improve-kvarn-k6v5-quality-and-speed` の深度 8K・128K の記録を含む）と、KVarN が KV メモリを減らすための機能で長文脈では FP16 KV より遅くなることが記載されている

#### Scenario: 封印ステップがレイテンシを突出させない
- **WHEN** 封印ステップを含む生成のトークン間レイテンシを、`kvarn-k5v4` テール長 2048 と `kvarn-k6v5` テール長 2048 のそれぞれで、同一負荷の FP16 KV と測定する
- **THEN** KVarN の p99 / p50 は FP16 KV の p99 / p50 の 1.05 倍以下である

#### Scenario: 主構成の並列スループットと起動時間が保たれる
- **WHEN** `kvarn-k5v4` テール長 2048 で C8 AR の合計スループット（利用者あたり文脈 4096）と、起動から HTTP 応答可能になるまでの時間を、FP16 KV と測定する
- **THEN** C8 AR の合計スループットは FP16 比 0.95 倍以上で、起動時間の悪化は 5% 以下である

#### Scenario: 深度 8K と 128K の速度が記録される
- **WHEN** `kvarn-k6v5` テール長 2048 の深度 8K と 128K で AR の tg と pp を、同じ測定系列の FP16 KV と交互に測定する
- **THEN** FP16 比がモデルの SHA-256 と測定条件とともに記録され、目標値による合否は課されない

#### Scenario: 変更が速度を落とさない
- **WHEN** 読み出しまたは量子化の変更の前後で、`kvarn-k6v5` テール長 2048 の深度 8K と 128K の tg と pp を同じ手法で測定する
- **THEN** 変更後の各 FP16 比は変更前の値の 0.97 倍以上であり、下回った変更は採用されない

#### Scenario: 既存の判定の繰り延べが記録される
- **WHEN** 変更 `improve-kvarn-k6v5-quality-and-speed` を完了する
- **THEN** 深度 0〜4K の AR の tg の下限、深度 32K 以上の tg と全深度の pp の基準値からの退行、p99 / p50、C8 AR の合計スループット、起動時間は同変更では判定されず、変更後のビルドでの再測定と後続の変更での適用が `BENCHMARKS.md` と `README.md` に記録されている

#### Scenario: FP16 の注意を置き換えた後に tg の基準値が測り直される
- **WHEN** FP16 KV の decode と検証行の注意を置き換えたビルドで、KVarN の読み出しを変更する前に、すべてのプリセット・テール長の深度 32K 以上の AR と DFlash2 の tg の基準値の点を同じ測定系列の FP16 KV と交互に測定する
- **THEN** 各点の FP16 比が新しい基準値として、置き換え前の基準値と並べてモデルの SHA-256 とともに `BENCHMARKS.md` に記録され、以後の判定ではこの基準値の 0.97 倍以上が要求され、pp の基準値は変わらない
